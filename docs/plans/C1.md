## Why this is first

The process defines a standard of evidence, *a test that has never been shown to fail is not evidence*, and ships no harness. The contract travels; the implementation is ours. The five capabilities come from `docs/conventions.md` § *Every project has a harness*.

| Capability | Done when |
|---|---|
| **run** | one command runs every Go and front-end check and exits non-zero on failure |
| **count** | one command prints the number of tests that actually **executed and passed**, across both runners |
| **floor** | a file holding a number the count may not fall below |
| **mutate** | at least one named way to break the code, paired with the test that catches it, run and recorded |
| **precommit** | a hook that runs the gates **after** the last edit |

`count` is separate from `run` on purpose: an exit code cannot show a suite that stopped running.

## Mutations proposed

| ID | Mutation | Must be caught by |
|---|---|---|
| M1 | `Version` returns an empty string | `internal/version` test |
| M2 | a Go test file whose only test is skipped, so the suite exits clean having proven nothing | the floor: count drops below `tests/TEST_FLOOR` |
| M3 | a commit whose subject reads `fix(D1): …` | `.githooks/commit-msg` refuses it |
| M4 | the status page edited by hand | `gen_status.py --check` fails in pre-commit and CI |
